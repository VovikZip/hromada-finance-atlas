# Hromada Finance Atlas

**Фінанси громади в одному місці.** Вебзастосунок, який збирає відкриті дані про доходи й видатки бюджету громади, показує їх за місяцями або за доступну частину року та дає посилання для перевірки цифр у першоджерелі.

> **Статус:** прототип. Він аналізує місцевий бюджет, а не весь рух грошей усіх установ і підприємств на території громади. «Залишок» на сторінці — розрахункова різниця між доходами й видатками, **не** залишок на банківських рахунках.

## Швидкий старт

Потрібні **Node.js 20.19+ або 22.12+**, **Python 3.10+** та інтернет для завантаження нових даних.

```bash
git clone https://github.com/VovikZip/hromada-finance-atlas.git
cd hromada-finance-atlas
npm ci
npm run dev
```

Відкрийте адресу `Local`, яку покаже термінал (зазвичай `http://127.0.0.1:5173/`). Команда запускає і React-інтерфейс, і локальний Python API. Щоб зупинити їх, натисніть `Ctrl+C`.

**Windows:** можна також запустити [START_HERE.bat](START_HERE.bat) подвійним кліком. Він установлює npm-залежності, якщо їх ще немає, збирає інтерфейс і відкриває сторінку. Для нового аналізу інтернет усе одно потрібен.

## Як користуватися

1. Знайдіть громаду за назвою або введіть її **10-значний код бюджету**. Наприклад, для Уманської громади — `2357400000`.
2. Оберіть рік і натисніть **«Провести аналіз»**. На сторінці видно етапи завантаження; запит можна скасувати.
3. У звіті перемикайте **«За місяць / За рік»**. Річний режим підсумовує тільки місяці, вже опубліковані в джерелі. Для порівняння є помісячні графік і таблиця.
4. Переглядайте надходження, витрати за КЕКВ і бюджетними програмами. Пошук у таблиці працює за назвою або кодом статті.

За потреби в розширених параметрах можна додати **ЄДРПОУ платника** й період для окремих платежів Spending. Це додаткова деталізація, а не частина суми, яку застосунок повторно додає до бюджетних видатків.

Звіт можна завантажити як **JSON** або **помісячний CSV**.

## Звідки беруться дані

| Джерело | Що використовує застосунок |
| --- | --- |
| [OpenBudget](https://openbudget.gov.ua/) · [API](https://api.openbudget.gov.ua/swagger-ui.html) | Довідник бюджетів, фактичні доходи й видатки за кодом бюджету. Це основа підсумкових сум. |
| [Spending](https://spending.gov.ua/) | Окремі платежі **лише** за вказаними ЄДРПОУ та датами. Не додаються вдруге до видатків OpenBudget. |

У розділі **«Джерела»** кожного звіту є посилання на бюджет в OpenBudget і конкретні запити, з яких отримано дані. Якщо джерело не надало даних за місяць, застосунок не підміняє їх нулем.

## Як розуміти показники

- **Надходження / витрати за місяць:** у січні — факт за січень, далі — різниця між накопиченим фактом цього й попереднього місяця. Якщо потрібного попереднього місяця в джерелі немає, значення не вигадується.
- **За рік:** сума доступних місячних фактів. Це не прогноз і не повний рік, доки не опубліковано всі 12 місяців.
- **«Залишок*»:** надходження мінус витрати за вибраний період. Для фактичного залишку на рахунках потрібні додаткові дані про початкові кошти й операції фінансування.
- **Туристичний збір:** лише доходи за кодами `18030100` і `18030200`, а не всі гроші від туризму.

Скрипт також звіряє підсумки за фондами, КЕКВ і програмами; знайдені розбіжності показує в попередженнях звіту.

## Що поки не охоплено

- Повний перелік платежів усіх установ громади: Spending шукає тільки за ЄДРПОУ, які ви додали.
- Кошти комунальних підприємств, кредити й операції фінансування бюджету.
- Договори Prozorro: договір не дорівнює фактичному платежу, тому він не входить у підсумкові суми.

## Командний запуск та файли звіту

Інтерфейс не обов’язковий. Для аналізу з термінала:

```bash
python -m func.hromada_atlas --budget-code 2357400000 --year 2026 --output-dir reports/uman-2026
```

У вказаній папці з’являться `report.json`, `monthly.csv`, `income_details.csv`, `expense_economic_details.csv` і `expense_program_details.csv`. Якщо додати `--payer-edrpou`, `--transactions-start` і `--transactions-end`, буде також `transactions.csv`. Папка `reports/` локальна й не потрапляє до Git.

## Розробка

Інтерфейс — **React + TypeScript + Vite** у `src/`. Запити й обрахунки — у `func/`; маршрути `api/` запускають той самий Python-обробник на Vercel. Локально `npm run dev` запускає обидві частини на `127.0.0.1`. На Vercel новий аналіз працює через серверні функції, а локальні файли `reports/` не є сховищем для онлайн-версії.

Для розгортання на Vercel використовуйте корінь цього репозиторію: `vercel.json` збирає Vite-інтерфейс і підключає Python API на тому самому домені. Окремий постійно запущений Python-сервер не потрібен. Якщо проєкт Vercel не підключено до GitHub для автоматичних деплоїв, після змін виконайте `vercel deploy --prod` у прив’язаній до проєкту папці. Для довгих відповідей OpenBudget серверна функція має ліміт 60 секунд; якщо джерело тимчасово повільне, повторіть аналіз.

```bash
npm run typecheck
npm run build
npm test
python -m unittest discover -s tests -v
```
