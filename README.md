# Hromada Finance Atlas — локальний прототип

## Найпростіший запуск

У папці проєкту один раз виконайте `npm install`, а потім запускайте `npm run dev`. Потрібні Python 3.10+ та Node.js 20.19+ або 22.12+ з npm. Команда одночасно підніме локальний Python API й React/Vite-сторінку; відкрийте адресу `Local`, яку покаже Vite (зазвичай `http://127.0.0.1:5173/`). Для нового аналізу потрібен інтернет. Термінал залишайте відкритим під час роботи.

На Windows також можна двічі клацнути [START_HERE.bat](START_HERE.bat): він збере інтерфейс, відкриє сторінку й запустить Python-сервер без режиму розробки. Там уже видно останній збережений звіт; щоб отримати свіжі дані, введіть код бюджету й рік і натисніть **«Провести аналіз»**.

Громаду можна знайти за назвою — наприклад, «Умань» або «Уманська» — і вибрати її зі списку офіційного [довідника місцевих бюджетів OpenBudget](https://api.openbudget.gov.ua/items/BUDG). Код бюджету підставиться автоматично. Ручне введення 10-значного коду теж залишається доступним; сторінка перевіряє його назву за тим самим довідником. Назва з’являється в заголовку звіту й повному JSON. Якщо довідник недоступний або код неоднозначний, назва не підставляється навмання; числовий аналіз за кодом залишається доступним.

На сторінці є перемикач **«За місяць / За рік»** для карток, структури надходжень і видатків та деталізації за кодами. Річний режим підсумовує тільки опубліковані місяці вибраного року; він не видає неповний рік за повний. Помісячні графік і таблиця залишаються для порівняння; натискання на рядок таблиці перемикає огляд на цей місяць. Також є найбільші бюджетні програми й пошук за кодом/назвою статті. Якщо додано Spending, можна шукати платежі за одержувачем і призначенням. Розподіл доходів на податкові, неподаткові, капітальні, трансферти й цільові фонди відповідає [бюджетній класифікації Мінфіну](https://zakon.rada.gov.ua/rada/show/v0011201-11): групу визначає перша цифра восьмизначного коду доходу.

Під час аналізу видно поточний етап, виконані етапи й час очікування. Етапи надходять із локального сервера; якщо зовнішнє джерело довго не відповідає, з’явиться попередження. Запит можна скасувати. Відсоток виконання не показуємо, бо час відповіді OpenBudget і Spending наперед невідомий.

Звіт на сторінці поділено на «Огляд», «По місяцях», «Структура», «Платежі» (якщо їх запитали) та «Джерела». У «Джерелах» є посилання на сторінку бюджету в OpenBudget, точні CSV-запити, документацію API й усі запити Spending, використані для транзакцій. Це дає змогу перевірити не лише назву сервісу, а й конкретні дані запиту.

Картка «Залишок*» показує **лише різницю надходжень і видатків за вибраний період**; поле `income_minus_expense_uah` у помісячному експорті — різницю за місяць. Це не фактичний залишок коштів на рахунку: для нього потрібні дані про початкові кошти й операції фінансування.

Якщо `.bat` не запускається, використайте `npm run dev` після `npm install`. Дані не публікуються в інтернеті: сторінка працює лише на цьому комп’ютері (`127.0.0.1`). Кнопки сторінки дозволяють завантажити JSON або помісячний CSV. Розширений командний запуск описаний нижче.

Це React/Vite-проєкт із TypeScript: інтерфейс — `src/App.tsx`, а типізовані запити, розрахунки, типи та Python API — у `func/`. Готова збірка потрапляє в `dist/` і обслуговується локальним Python-сервером. `npm run dev` сам обирає вільний порт для API та проксіює `/api` через Vite. Для перевірки типів: `npm run typecheck`; для збірки: `npm run build`.

Скрипт аналізує **фактичні доходи та видатки місцевого бюджету за місяцями**. Він працює з офіційним [OpenBudget API](https://api.openbudget.gov.ua/swagger-ui.html), а за бажанням додає деталізацію окремих платежів із [Spending API](https://data.gov.ua/dataset/bff70377-03d0-499e-b703-e37ce25e7e46/resource/324ba843-f23d-4161-9e21-ec221819a431). Потрібен Python 3.10+; додаткові пакети не потрібні.

Приклад для [бюджету Уманської громади (код 2357400000)](https://openbudget.gov.ua/local-budget/2357400000/info/profile):

```powershell
python -m func.hromada_atlas --budget-code 2357400000 --year 2026 --output-dir reports/uman-2026
```

Окремо підтягнути транзакції виконавчого комітету (ЄДРПОУ 04061613) за один місяць:

```powershell
python -m func.hromada_atlas --budget-code 2357400000 --year 2026 --payer-edrpou 04061613 --transactions-start 2026-10-01 --transactions-end 2026-10-31 --output-dir reports/uman-2026
```

Можна повторювати `--payer-edrpou` для кількох установ. Код бюджету та ЄДРПОУ — різні ідентифікатори: код бюджету дає зведення всієї громади, а ЄДРПОУ обмежує пошук окремих транзакцій конкретними платниками.

## Результат

- `monthly.csv` — доходи, видатки, їх розрахункова різниця та туристичний збір помісячно;
- `income_details.csv` — доходи за кодами класифікації;
- `expense_economic_details.csv` — видатки за КЕКВ;
- `expense_program_details.csv` — видатки за бюджетними програмами;
- `transactions.csv` — окремі платежі, лише якщо задано платників і дати;
- `report.json` — ті самі дані, адреси запитів, покриття і попередження.

Суми у гривнях, без округлення під час розрахунків; у файлах — два знаки після коми. Файли CSV записуються як UTF-8 з BOM, щоб український текст відкривався в Excel.

## Як рахується місяць

Поле `FAKT_AMT` OpenBudget є фактом **наростаючим підсумком**. Тому факт за лютий = факт за січень–лютий мінус факт за січень. Для першого доступного місяця, якщо це не січень, місячну суму скрипт не вигадує. Відсутній місяць не стає нулем. Для перевірки скрипт звіряє фонд `T` із `C+S` та підсумки видатків за КЕКВ і програмами. Невідповідності потрапляють до `warnings` у JSON.

Для програм беруться тільки підсумкові рядки `COD_CONS_EK=0000`, інакше той самий видаток дублювався б деталізацією КЕКВ. Туристичний збір рахується лише за кодами доходів `18030100` і `18030200` — це **не повна сума грошей від туризму**.

## Межі цього прототипу

- Бюджетні суми OpenBudget — головний підсумок. Платежі Spending — додатковий розріз і **не додаються** до видатків повторно.
- Spending тут охоплює тільки передані ЄДРПОУ. Автоматичного повного переліку установ громади поки немає.
- Договори Prozorro не є фактичними платежами й у ці суми не включені. Дані комунальних підприємств, фінансування бюджету та кредити також поки не охоплені.
- API може опублікувати останній місяць із затримкою. Скрипт показує тільки місяці, реально наявні у відповіді, а не припускає, що поточний місяць уже закритий.
- Зіставлення доходів із видатками не дорівнює бюджетному профіциту/дефіциту: для цього потрібні також операції фінансування та інші бюджетні показники.

Перевірка локальної логіки:

```powershell
python -m unittest discover -s tests -v
npm test
```
